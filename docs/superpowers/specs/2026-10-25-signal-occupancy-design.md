# Signal entry and physical occupancy

Replace signal entry reservations with light permissions and normal following. Green admits streams, yellow makes a per-approach stop/go decision from comfortable stopping distance, and red denies new entry. Track actual front-entered/rear-not-cleared vehicles separately from stop/yield claims; remaining crossing traffic blocks conflicting entry, while same-approach traffic follows normally. Stop/yield and merge controls retain their existing arbitration.

The user selected this rewrite following review of f0ae7aa and requested a measured old/new performance comparison. Repair scheduler and integration defects alongside entry control: scheduled requests activate at the next completed phase clearance, the latest pending request wins, ticks split at controller events, blank controllers fail closed, and legal signal waits never trigger deadlock overrides. Protected green and yellow groups are validated against geometry so simultaneous incompatible permissions cause a configuration error instead of silently relying on reservations.

Approaches considered: retaining provisional claims leaves duplicate permission state; changing every junction to a new traffic engine exceeds scope. Use dedicated physical signal occupancy in the existing coordinator and shared helpers for both update engines. Implement in existing Python modules with no new runtime dependencies. The author chooses a comfortable-braking yellow threshold without introducing a driver reaction calibration model.

Validation must cover platoons, slow pre-entry vehicles, actual rear clearance, opposing traffic, yellow stopping and continuing, scheduled changes during each aspect, non-grid event times, missing controllers, ordinary red waits, removals, and non-signal regressions. Compare current main against the rewrite using identical seeded demand, separated CPU and throughput metrics, and identical frozen traffic states for CPU-only cost.
